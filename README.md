# CFO جیبی (Pocket CFO)

یک ربات تلگرامی شخصی برای ثبت روزمره‌ی هزینه‌ها — مثل یک مدیر مالی جیبی که هر روز
با او حرف می‌زنی. کافی است یک **ویس** بگیری یا یک **متن** بفرستی و بگویی چه خرجی
کرده‌ای؛ ربات از حرفت تراکنش‌ها را استخراج می‌کند، برای هر کدام یک «کارت تأیید»
می‌فرستد و بعد از تأیید تو، آن را در دیتابیس ثبت می‌کند.

## ایده‌ی اصلی
- **سه نوع کارت، یک ورودی.** هر پیام (متن یا ویس) از یک تشخیصِ نیت می‌گذرد و به شاخه‌ی
  درستش می‌رود: **تراکنش** (پول جابه‌جا شد)، **بدهی/طلب** (پول قرار است بعداً برگردد)،
  یا **هدف** (سقف بودجه‌ی ماهانه). یک ویس می‌تواند هر سه را با هم داشته باشد؛ آن‌وقت سه
  کارتِ جدا ساخته می‌شود.
- **هر تراکنش = یک بار کارت کشیدن**، نه تک‌تک اقلام. اگر از سوپرمارکت چند چیز با یک
  پرداخت بخری، یک تراکنش است و اقلام به‌عنوان متادیتا ذخیره می‌شوند.
- **مبلغ و عنوان اجباری‌اند** و قبل از ثبت باید تأیید انسانی شوند (با قابلیت ویرایش).
- مبلغ همیشه با جداکننده‌ی هزارگان و واحد (تومان/ریال) نشان داده می‌شود تا از خطای
  صفرها جلوگیری شود.
- **تگ‌گذاری خودکار:** مدل از یک «بانک تگ» موجود نزدیک‌ترین تگ‌ها را انتخاب می‌کند؛
  کد به‌صورت قطعی اعتبارسنجی و تطبیق می‌کند و هر چیز ناشناخته به صف پیشنهاد می‌رود.
- **یادآوری شبانه‌ی هوشمند:** فقط تراکنش‌هایی که ناقص‌اند یا گفته‌ای بعداً کامل می‌کنی.

## بدهی و طلب
کافی است طبیعی حرف بزنی: «۵۰۰ به سعید قرض دادم» → کارتِ **طلب**؛ «۲ میلیون به فروشگاه
بدهکارم» → کارتِ **بدهی**. مبلغ و طرفِ حساب اجباری‌اند (تا وقتی یکی نباشد، کارت خطِ
«نیازمند تکمیل» می‌گیرد). بعداً می‌توانی بگویی «بدهیم به رضا رو دادم» یا «نصفش رو دادم»
— سیستم همان رکوردِ باز را پیدا می‌کند و کامل یا جزئی تسویه‌اش می‌کند (بدون رکوردِ تکراری).
دکمه‌ی «✅ تسویه شد» هم روی خودِ کارت هست.

## خانوار (مالیِ مشترک)
دو اکانت می‌توانند به هم وصل شوند و یک **دفترِ مالیِ مشترک** داشته باشند:

- دکمه‌ی **«👨‍👩‍👧 افزودن عضو به خانوار»** → انتخاب نسبت (پارتنر/همسر، عضو خانواده، …) →
  انتخاب سطح دسترسی (آیا اجازه‌ی هدف‌گذاری دارد؟) → تولید یک **لینک دعوتِ یک‌بارمصرف**.
- لینک را در تلگرام برای طرفِ مقابل می‌فرستی؛ با یک کلیک وارد ربات می‌شود و با همان
  دسترسی‌های از پیش تعیین‌شده عضو خانوار می‌شود (نیازی نیست آی‌دی‌اش را دستی به
  `ALLOWED_USER_IDS` اضافه کنی — خودِ لینک مجوزِ ورود است).
- از آن لحظه هر **تراکنش، بدهی/طلب و هدفِ** هر دو نفر در همان دفتر جمع می‌شود؛ فقط
  «ثبت‌کننده» جدا ذخیره می‌شود و روی کارت‌ها و در گزارش («👥 به تفکیک ثبت‌کننده») می‌آید.
- عملکرد **تجمعی** است: اگر یکی هدفِ «سقف رستوران» بگذارد، خرجِ رستورانِ **هر دو** در همان
  لیمیت حساب می‌شود و هشدارهای ۵۰٪/۸۰٪/۱۰۰٪ برای **هر دو اکانت** فرستاده می‌شود.
- `/household` وضعیت خانوار و دسترسیِ هر عضو را نشان می‌دهد.

پشتِ صحنه هر کاربر — حتی تنها — عضو یک «خانوار» است (تک‌نفره)، تا کلِ سیستم یک‌شکل بماند
و پیوستنِ پارتنر چیزی را نشکند. دیتای دفترِ قبلیِ عضوِ تازه هم موقعِ پیوستن به دفترِ
مشترک منتقل می‌شود.

## معماری
```
bot/
  config.py            # بارگذاری .env
  main.py              # راه‌اندازی Application و JobQueue
  utils/money.py       # parse/format مبلغ، واحد تومان/ریال
  db/                  # schema.sql + repo.py (SQLite)
  llm/                 # client (زنجیره‌ی fallback) + router (نیت) + extract + prompts
  services/            # transactions, debts, goals, household, tags, reports, reminders
  flows/               # رندر سه کارت: draft_flow (تراکنش)، goal_card، debt_card
  handlers/            # commands, messages (ویس/متن), callbacks, keyboards, cards
data/tags_seed.json    # بانک تگ سلسله‌مراتبی اولیه
tests/                 # تست‌های واحد: money, tags, goals, debts, household, intents
```

### زنجیره‌ی LLM (Fallback)
درخواست رونویسی+تحلیل ویس در **یک** کال به مدل زده می‌شود:
1. `google/gemini-2.5-flash` (تایم‌اوت ۱۵ ثانیه)
2. همان مدل، پس از ۵ ثانیه وقفه
3. `google/gemini-2.5-flash-lite`
4. در صورت شکست همه → پیام «سرویس‌های هوش مصنوعی پاسخگو نیستند…»

## راه‌اندازی
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # سپس مقادیر را پر کن
python -m bot.main
```

### پر کردن `.env`
- `TELEGRAM_BOT_TOKEN` را از [@BotFather](https://t.me/BotFather) بگیر.
- `OPENROUTER_API_KEY` را از [openrouter.ai/keys](https://openrouter.ai/keys) بگیر.
- `ALLOWED_USER_IDS` را با آی‌دی عددی تلگرام خودت پر کن (از [@userinfobot]). اگر
  خالی بماند ربات به همه پاسخ می‌دهد.

> فایل `.env` در `.gitignore` است و هیچ‌وقت به گیت push نمی‌شود. کلیدها را فقط
> یک‌بار اینجا می‌گذاری.

### چه کسی می‌تواند از ربات استفاده کند
محدودیتِ فعلی **موقت** است (مرحله‌ی شخصی/بتا) و کلیدِ کنترلش در `bot/config.py` است،
نه روی سرور:

| می‌خواهی… | کاری که باید بکنی |
|---|---|
| یک نفر را اضافه کنی | آی‌دی‌اش را به `EXTRA_ALLOWED_USER_IDS` اضافه کن و push کن |
| ربات را برای **همه** باز کنی | `ACCESS_MODE = ACCESS_OPEN` و push کن — همین |
| دوباره محدودش کنی | `ACCESS_MODE = ACCESS_ALLOWLIST` |

آی‌دی‌های `EXTRA_ALLOWED_USER_IDS` با `ALLOWED_USER_IDS`ِ `.env` **جمع** می‌شوند (اگر
`.env` خالی باشد یعنی ربات عمداً باز است و کد آن را محدود نمی‌کند). آی‌دی عددی تلگرام
محرمانه نیست، پس مثل بقیه‌ی تنظیمات در کد می‌ماند تا اضافه‌کردنِ کسی فقط یک push باشد.

ربات موقع راه‌اندازی وضعیتِ مؤثرش را لاگ می‌کند، پس همیشه می‌شود با
`docker logs pocket-cfo | head` فهمید الان باز است یا محدود:

```
دسترسی: محدود به ۲ آی‌دی (…) + اعضای خانوارشان
```

> این‌ها فقط **اجازه‌ی استفاده** از ربات‌اند. شریک‌شدن در دفتر مالی کارِ لینکِ دعوتِ
> خانوار است، نه این لیست.

## دیپلوی روی سرور
استقرار خودکار با **Docker + GitHub Actions** روی یک VPS خارجی انجام می‌شود (ربات با
polling کار می‌کند، پس دامنه/HTTPS لازم نیست). راهنمای کامل و یک‌بارهٔ راه‌اندازی در
[`DEPLOY.md`](DEPLOY.md) است. خلاصه: داکر را روی سرور نصب کن، `.env` را روی سرور بساز،
سه Secret (`SSH_HOST`/`SSH_USER`/`SSH_KEY`) را در گیت‌هاب بگذار، و یک push بزن.

اجرای محلی با داکر:
```bash
cp .env.example .env   # پرش کن
docker compose up --build
```

## یادداشت فنی: ورودی صوتی از طریق OpenRouter
جمینای ذاتاً ورودی صوتی را پشتیبانی می‌کند، اما پشتیبانی OpenRouter از فرمت
`ogg/opus` تلگرام باید در عمل تست شود. لایه‌ی `bot/llm/client.py` انتزاعی است؛ در
صورت نیاز با تغییر `OPENROUTER_BASE_URL`/مدل به Google Gemini مستقیم سوییچ کن.
