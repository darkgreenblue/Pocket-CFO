# میان‌برِ iOS — ثبتِ خرج با سه ضربه پشتِ گوشی

سه ضربه پشتِ آیفون → یک باکس باز می‌شود → حرف می‌زنی یا تایپ می‌کنی → خرج ثبت می‌شود و
کارتِ تأییدش در تلگرام منتظرت می‌ماند.

## چرا این‌طوری کار می‌کند (و نه با API تلگرام)

نمی‌شود از شرتکات «به‌جای تو» به ربات پیام داد: `sendMessage` در Bot API پیام را **از
طرفِ ربات** می‌فرستد، نه از طرفِ تو، و هیچ updateای برای ربات نمی‌سازد. پس جهتِ ترافیک
را برعکس کردیم:

```
گوشی ──HTTP──▶ سرورِ ما ──▶ دیتابیس
                   │
                   └──▶ تلگرام (کارتِ تأیید برای تو)
```

فایده‌ی جانبی‌اش مهم است: **گوشیِ تو لازم نیست به تلگرام دسترسی داشته باشد.** فقط باید
به سرورِ خودمان برسد. سرور خودش به تلگرام وصل است، پس کارت را می‌فرستد و هر وقت بعداً
تلگرام را باز کردی، آنجا منتظرت است.

## قدم ۰ — اول این را تست کن

قبل از هر چیز مطمئن شو گوشی اصلاً به سرور می‌رسد. در Safari گوشی (بدون VPN) باز کن:

```
http://<آی‌پی-سرور>:8081/health
```

اگر `{"ok": true}` دیدی، بقیه‌اش کار می‌کند. اگر ندیدی، بقیه‌ی این راهنما بی‌فایده است
و باید اول مسیرِ شبکه را حل کنیم (مثلاً Cloudflare Tunnel).

## قدم ۱ — ساختنِ توکن روی سرور

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

خروجی را در `.env` سرور بگذار، کنارِ آی‌دی عددیِ تلگرامت:

```
INGEST_TOKENS=123456789:<توکن>
```

برای دو نفر با `,` جدا کن: `INGEST_TOKENS=111:tokA,222:tokB`. هر کس توکنِ خودش را
دارد و خرجش با نامِ خودش در دفترِ خانوار ثبت می‌شود.

سپس `docker compose up -d --build`. اگر `INGEST_TOKENS` خالی باشد، سرورِ HTTP اصلاً
بالا نمی‌آید — یعنی این قابلیت تا وقتی توکن نگذاری خاموش است.

> پورت `8081` باید در فایروالِ سرور باز باشد.

## قدم ۲ — ساختنِ شرتکات

در اپ Shortcuts یک شرتکات تازه به اسم «ثبت خرج» بساز:

| # | اکشن | تنظیم |
|---|------|-------|
| ۱ | **Dictate Text** | زبان: Persian |
| ۲ | **Text** | متنِ دیکته‌شده را بگیرد (`Dictated Text`) |
| ۳ | **Get Contents of URL** | پایین توضیح داده شده |
| ۴ | **Show Notification** | فیلدِ `message` از پاسخ |

تنظیماتِ **Get Contents of URL**:

- **URL:** `http://<آی‌پی-سرور>:8081/ingest`
- **Method:** `POST`
- **Headers:** `Content-Type` = `application/json`
- **Request Body:** `JSON` با این فیلدها:
  - `token` (Text) → توکنی که ساختی
  - `request_id` (Text) → یک UUID تازه. با اکشن **UUID** بساز و همین‌جا پاسش بده.
  - `text` (Text) → خروجیِ Dictate Text

`request_id` را حتماً بگذار: اگر شبکه قطع شد و دوباره فرستادی، همان درخواست دوباره
ثبت نمی‌شود.

### حالتِ ویس (به‌جای دیکته)

اگر دیکته‌ی فارسیِ اپل خوب درنیامد، به‌جای Dictate Text از این‌ها استفاده کن:

| # | اکشن |
|---|------|
| ۱ | **Record Audio** (Start/Stop: `Ask When Run`) |
| ۲ | **Base64 Encode** |
| ۳ | **Get Contents of URL** با بدنه‌ی `audio_b64` + `audio_format` = `m4a` |

فرقشان: دیکته روی خودِ گوشی انجام می‌شود (سریع، چند صد بایت آپلود)، ولی ویس را مدل
رونویسی می‌کند (کیفیتِ فارسیِ بهتر، چند صد کیلوبایت آپلود). با اینترنتِ کند، دیکته
انتخابِ بهتری است.

### هر دو با هم

اکشن **Choose from Menu** با دو گزینه‌ی «ویس» و «تایپ» بگذار و هر شاخه را به یکی از
دو حالتِ بالا وصل کن. برای تایپ از **Ask for Input** استفاده کن.

## قدم ۳ — وصل‌کردن به سه ضربه‌ی پشتِ گوشی

`Settings › Accessibility › Touch › Back Tap › Triple Tap` → شرتکات «ثبت خرج» را
انتخاب کن.

> گوشی باید آنلاک باشد تا Dictate/Ask for Input کار کند.

## گیرهای شناخته‌شده

**اگر ارسال شکست بخورد، ورودی گم می‌شود.** شرتکات try/catch ندارد و با خطا متوقف
می‌شود. راهِ در رفتن: قبل از **Get Contents of URL** یک اکشن **Append to Text File**
بگذار که متن را در یک فایلِ محلی هم بنویسد. اگر ارسال نرفت، متن دستِ کم پیشِ خودت
هست.

**فقط ثبتِ خرج.** از این مسیر عمداً هیچ چیزِ دیگری روی دیتابیس اثر نمی‌گذارد — نه
بدهی/طلب، نه هدف، نه ویرایشِ تراکنشِ قبلی. اگر چیزی جز خرج گفتی، ربات در تلگرام
همان متن را برایت می‌فرستد تا گم نشود و آنجا ادامه بدهی.

**سقفِ روزانه.** همان سقفِ همیشگی اینجا هم اعمال می‌شود. اگر تمام شده باشد، ورودی در
صف می‌ماند و صبح یکجا ثبت می‌شود؛ شرتکات هم همین را به تو می‌گوید.

**HTTP ساده یعنی توکن روی شبکه قابلِ شنود است.** این توکن کلیدِ نوشتن روی دفترِ
مالی است. برای فازِ تست قابل قبول است؛ برای استفاده‌ی دائمی TLS بگذار.

## پاسخ‌های سرور

| کد | `status` | یعنی |
|----|----------|------|
| ۲۰۰ | `recorded` | ثبت شد، کارت در تلگرام رفت |
| ۲۰۰ | `queued` | سهمیه‌ی روزانه تمام شده؛ صبح ثبت می‌شود |
| ۲۰۰ | `nothing` | خرجی پیدا نشد؛ متنش در تلگرام فرستاده شد |
| ۲۰۰ | `duplicate` | همین `request_id` قبلاً ثبت شده |
| ۴۰۱ | — | توکن نامعتبر |
| ۴۲۹ | `rate_limited` | خیلی سریع پشتِ هم فرستادی |

## تستِ دستی با curl

```bash
curl -s http://<آی‌پی>:8081/health

curl -s -X POST http://<آی‌پی>:8081/ingest \
  -H 'Content-Type: application/json' \
  -d '{"token":"<توکن>","request_id":"test-1","text":"ناهار ۲۵۰ هزار تومن"}'
```
